# BM25 from first principles

`LocalBM25` tokenizes NFKC-normalized, case-folded text with a regex that keeps
legal identifiers such as `12.3(a)`, words, numbers, hyphenated terms, and
Devanagari text. It materializes the authorized chunk set for the request.

For term `t` in document `d`, the implementation uses:

`IDF(t) = log(1 + (N - df(t) + 0.5)/(df(t) + 0.5))`

`score(t,d) = IDF(t) * tf*(k1+1) /
             (tf + k1*(1-b+b*|d|/avgdl))`

with `k1=1.2`, `b=0.75`. TF is term frequency, DF is the number of documents
containing the term, and length normalization prevents long chunks winning only
because they repeat words. Scores are sorted descending with chunk UUID as the
deterministic tie-breaker.

BM25 is strong for exact clause numbers, names, dates, amounts, identifiers,
and quoted language. Dense embeddings capture paraphrase but can miss an exact
numeric/legal token; hybrid retrieval covers both failure modes. ICIA deliberately
does not build a persistent sparse index yet: measured scale should justify
PostgreSQL FTS or a dedicated search system first.
